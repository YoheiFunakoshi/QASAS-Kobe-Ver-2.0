# 汎用レパトアExcelと変換アプリの将来計画

## 1. この文書の位置付け

この文書は、QASAS Kobe Ver 2.0に表示している`汎用形式（今後対応）`ボタンの目的と、将来作成する「多様なレパトア形式をQASAS用の汎用Excelへ変換するアプリ」の初期計画を残すものです。

現時点では計画書であり、汎用Excelの最終仕様や汎用ローダーの実装完了を意味しません。仕様を確定した時点で形式バージョンを付け、実装・試験・移行手順を追記します。

この文書は検体レパトアの整理計画です。抗体・BCR配列データベースの整理は別アプリ・別形式とし、[汎用抗体データベースExcelと整理アプリの将来計画](GENERIC_DATABASE_FORMAT_PLAN.md)に記録します。

## 2. 目的

QASASの基本入力は、現在次の2形式です。

- RG社形式: `Back_data`シートを持つExcel
- CPM社形式: Vコール、Jコール、CDR3 AA、カウント列を持つCSV/TSV

今後は会社、解析ソフト、研究施設ごとに異なるレパトア形式が追加される可能性があります。各形式の読込処理をQASAS本体へ個別に増やし続けると、解析の再現性、保守性、入力形式の判別が複雑になります。

そこで、形式差を別の変換アプリで吸収し、QASASには標準化済みの汎用Excelだけを渡す構成とします。

```text
各社・各解析ソフトの元レパトア
        ↓
汎用形式変換アプリ
  - 入力形式の選択または自動判定
  - 必要列の対応付け
  - 値とカウント単位の検証
  - 変換履歴の記録
        ↓
QASAS汎用Excel
        ↓
QASAS Kobeの「汎用形式」
```

## 3. 役割分担

### 汎用形式変換アプリ

- 多様な元ファイルを読み取る
- Vコール、Jコール、CDR3アミノ酸配列、リード数／カウント数を対応付ける
- 元データを上書きせず、新しい汎用Excelを出力する
- 欠損、不正な配列、0以下のカウント、列の取り違えを検出する
- カウントの意味と変換元を記録する

### QASAS Kobe

- RG社形式は既存のRGローダーで読み込む
- CPM社形式は既存のCPMローダーで読み込む
- その他の形式は、変換アプリが出力した汎用Excelだけを読み込む
- 未知の生ファイルを`汎用形式`として推測読込しない
- 形式バージョンと必須項目を検証してから解析する

この分離により、入力変換とQASAS照合を別工程として監査できます。

## 4. 汎用Excelの初期仕様案

最初の対象はヒト免疫グロブリン重鎖（IGH）レパトアを想定します。最終的な列名とシート名は実装開始時に固定します。

### `Repertoire`シートの必須項目

| 初期列名案 | 内容 | 基本規則 |
|---|---|---|
| `V_CALL` | Vコール | 元データに存在する遺伝子・アレル情報を保持 |
| `J_CALL` | Jコール | 元データに存在する遺伝子・アレル情報を保持 |
| `CDR3_AA` | CDR3アミノ酸配列 | アミノ酸配列として保持し、塩基配列と混同しない |
| `COUNT` | リード数／カウント数 | 数値かつ0より大きい値 |

この4項目が解析用の最小情報です。変換アプリは、どの元列を各項目へ割り当てたか記録します。

### 行単位で保持することを推奨する項目

| 初期列名案 | 目的 |
|---|---|
| `COUNT_UNIT` | `read`、`UMI family`、`clone count`など、COUNTの観測単位を明示 |
| `SOURCE_ROW` | 元ファイルの行番号またはレコードID |
| `V_CALL_RAW` | 変換前のVコール文字列 |
| `J_CALL_RAW` | 変換前のJコール文字列 |
| `CDR3_AA_RAW` | 変換前のCDR3 AA文字列 |
| `COUNT_RAW` | 変換前のカウント表記 |
| `PRODUCTIVE` | productive／in-frameの判定が元データにある場合の記録 |

元データの監査性を守るため、変換アプリでは原則として入力レコードを勝手に集約しません。QASAS側で必要なクローン集約を行います。変換段階で集約する場合は、その規則と集約前後の件数を必ず記録します。

### `Metadata`シートの推奨項目

| 初期項目名案 | 内容 |
|---|---|
| `FORMAT_VERSION` | 例: `QASAS_GENERIC_1.0` |
| `SAMPLE_ID` | 検体識別子 |
| `CHAIN` | 初期対象では`IGH` |
| `COUNT_UNIT` | ブック全体で共通のカウント単位 |
| `TOTAL_COUNT_DENOMINATOR` | 頻度計算の分母。行COUNT合計と異なる場合に必須 |
| `SOURCE_FORMAT` | 元の会社名、解析ソフト名、出力形式名と版 |
| `SOURCE_FILE` | 元ファイル名 |
| `SOURCE_SHA256` | 元ファイルの同一性確認用ハッシュ |
| `CONVERTER_VERSION` | 変換アプリの版またはGitコミット |
| `CONVERTED_AT` | 変換日時 |
| `NOTES` | フィルターや特記事項 |

### `Validation`シートの推奨項目

- 元レコード数
- 出力レコード数
- 除外レコード数と理由別件数
- 元COUNT合計
- 出力COUNT合計
- V／J／CDR3 AA／COUNTの欠損件数
- 不正値の件数
- 警告と変換時の判断内容

## 5. 重要な意味上の規則

### Vコール・Jコール

- 元データにアレル情報がある場合は保持します。
- 元データにアレル情報がない場合、根拠なく`*01`などを補いません。
- 複数候補がある場合は、元文字列を`*_RAW`へ残し、標準列で使用する区切り規則を形式仕様に固定します。
- RG、CPM、旧QASAS、Kobe方式でアレルの扱いが異なるため、変換段階の加工とQASAS照合時の正規化を混同しません。

### CDR3 AA

- アミノ酸配列と塩基配列を区別します。
- 大文字化や空白除去などの機械的処理は記録します。
- C／Wなどの端部を含むかどうかは元データを保持し、無断で切り落としません。
- 停止コドン、不明残基、空欄を検出し、採用・除外規則をValidationへ残します。

### COUNTと頻度

- Read数、UMI family数、クローン数は別の観測単位であり、同じ`COUNT`として無説明に混在させません。
- `COUNT_UNIT`を必ず確認できるようにします。
- 頻度列をCOUNTの代用にはしません。
- 頻度の分母がCOUNT合計と異なる形式では、`TOTAL_COUNT_DENOMINATOR`と分母の定義を記録します。
- 単位が不明な場合は推測せず、変換を停止するか明確な警告を出します。

## 6. 変換アプリの画面・処理案

1. 元ファイルを選択する
2. 入力形式を自動判定または一覧から選択する
3. シート、ヘッダー行、V、J、CDR3 AA、COUNT列をプレビューする
4. 自動対応付けの結果を利用者が確認・修正する
5. COUNT単位、productive／in-frameの扱い、除外規則を指定する
6. 変換前の検証結果を表示する
7. 元ファイルとは別の場所へ汎用Excelを保存する
8. 汎用ExcelとValidationを再読込し、出力が仕様に合うことを確認する

入力形式ごとの処理はアダプターとして分離し、新しい形式を追加しても既存形式の変換結果が変わらない構造を目標とします。

## 7. QASASの「汎用形式」ボタン

現在のQASAS Kobe Ver 2.0では、単独検体画面と経時・複数検体画面に`汎用形式（今後対応）`ボタンを表示しています。

- 現在は無効状態であり、解析処理はありません。
- 将来の汎用Excel入力場所をGUI上で予約するためのボタンです。
- 汎用Excel仕様とローダーの試験が完了するまで有効化しません。
- 有効化後は、汎用Excel以外の生ファイルを選んだ場合に明確なエラーを表示します。
- 経時解析では各時点の入力形式、形式バージョン、カウント単位を結果へ記録します。

## 8. ボタンを有効化するための完了条件

- 汎用Excelの形式バージョンと必須列が確定している
- V、J、CDR3 AA、COUNT、COUNT単位の検証規則が確定している
- 汎用Excelを読み込む専用ローダーが実装されている
- 欠損、不正値、未知バージョンを安全に拒否できる
- RG／CPMと同じ既知データを汎用形式へ変換し、意図した範囲で解析結果が一致する
- 行数とCOUNT合計を元データから汎用Excel、QASAS読込後まで追跡できる
- 単独解析と経時解析の両方で試験に合格する
- README、形式仕様、操作手順、テストデータが揃っている

## 9. 実装時の段階案

1. 実際に追加する複数形式のサンプルを収集し、列と単位を比較する
2. `QASAS_GENERIC_1.0`の列名、シート名、許容値を確定する
3. 変換アプリの共通検証エンジンと最初の形式アダプターを作る
4. プレビュー、列対応付け、Validation出力を作る
5. 元データと変換結果の件数・カウントを形式ごとに検証する
6. QASAS汎用ローダーを実装する
7. `汎用形式`ボタンを有効化し、単独・経時解析へ接続する
8. 再現性情報とExcel出力へ形式バージョン・単位を記録する

## 10. 実装開始時に最終決定する事項

- 正式なシート名と列名
- COUNT単位の許容語彙
- 複数V/J候補の表現方法
- productive／in-frame行の扱い
- CDR3 AAの許容文字と端部処理
- 同一V/J/CDR3行を変換段階で集約するか
- 分母情報が存在しない形式の頻度計算
- 検体情報を1ファイル1検体に限定するか
- エラーと警告の境界

これらは実データを確認せずに固定せず、入力形式ごとの仕様と研究上のカウント単位を確認して決定します。
