# 汎用抗体データベースExcelと整理アプリの将来計画

## 1. この文書の位置付け

この文書は、QASAS Kobe Ver 2.0の`汎用データベース（今後対応）`ボタンと、将来作成する「多様な抗体・BCR配列データベースをQASAS用の汎用データベースExcelへ整理するアプリ」の初期計画を残すものです。

現時点では計画書であり、汎用データベースExcelの最終仕様、整理アプリ、QASAS汎用データベースローダーは未実装です。実際の追加データベースを確認してから形式バージョンと列仕様を確定します。

## 2. 現在のデータベースと目的

現在の基本データベースはCoV-AbDab由来CSVです。QASASはデータベースのVコール、Jコール、CDR3アミノ酸配列を検体レパトアと照合します。

CoV-AbDabには抗体名、結合対象、中和情報、エピトープ、出典など多数の列がありますが、照合を実行するための最小情報は次の3項目です。

- Vコール
- Jコール
- CDR3アミノ酸配列

抗体データベースは検体レパトアではないため、Read数やクローン数などのCOUNTは必須ではありません。元データベースに件数情報がある場合も、検体頻度の計算には使用せず、意味を明記した注釈として扱います。

## 3. 将来の全体構成

```text
各機関・各公開資源・各研究で作成された抗体/BCR配列データベース
        ↓
データベース整理アプリ
  - 入力形式の選択または自動判定
  - V/J/CDR3 AA列の対応付け
  - 注釈列の対応付け
  - 配列と必須項目の検証
  - 元情報と変換履歴の記録
        ↓
QASAS汎用データベースExcel
        ↓
QASAS Kobeの「汎用データベース」
```

QASAS本体は、未知の生データベースを推測して直接読み込みません。形式差は整理アプリで吸収し、QASASは仕様に適合した汎用データベースExcelだけを読み込みます。

## 4. レパトア整理アプリとの区別

| 項目 | レパトアデータ整理アプリ | データベース整理アプリ |
|---|---|---|
| 対象 | 検体のレパトア解析結果 | 抗原結合性が既知の抗体/BCR配列集 |
| 最小必須情報 | V、J、CDR3 AA、COUNT | V、J、CDR3 AA |
| COUNT | Read、UMI family、クローン数などの単位が重要 | 原則不要。存在する場合は注釈 |
| 頻度 | 検体内頻度を計算する | 計算しない |
| 主な追加情報 | Sample ID、COUNT単位、分母 | DB ID、抗体名、抗原、出典 |
| QASASでの役割 | 検索される検体クローン | 照合先となる既知配列 |

2つの整理アプリは別アプリとして作り、出力Excelも別の形式バージョンを使用します。

## 5. 汎用データベースExcelの初期仕様案

### `Sequences`シートの必須項目

| 初期列名案 | 内容 | 基本規則 |
|---|---|---|
| `V_CALL` | Vコール | 元データにある遺伝子・アレル情報を保持 |
| `J_CALL` | Jコール | 元データにある遺伝子・アレル情報を保持 |
| `CDR3_AA` | CDR3アミノ酸配列 | 塩基配列と区別し、空欄を許容しない |

この3項目がQASAS照合に必要な最小情報です。3項目のいずれかが欠ける行は、通常のV/J/CDR3照合キーを作れません。

### 強く推奨する識別・注釈項目

| 初期列名案 | 目的 |
|---|---|
| `DB_ID` | データベース内で行または抗体を一意に追跡 |
| `NAME` | 抗体名、クローン名、配列名 |
| `TARGET_ANTIGEN` | 結合対象の抗原、ウイルス、タンパク質など |
| `BINDING` | 結合する対象と根拠 |
| `NON_BINDING` | 結合しないことが確認された対象 |
| `EPITOPE` | タンパク質領域またはエピトープ |
| `NEUTRALIZATION` | 中和対象と活性情報 |
| `NON_NEUTRALIZATION` | 非中和対象 |
| `SPECIES` | 抗体またはBCR配列の由来種 |
| `SOURCE` | 論文、DOI、URL、登録番号など |
| `V_CALL_RAW` | 整理前のVコール文字列 |
| `J_CALL_RAW` | 整理前のJコール文字列 |
| `CDR3_AA_RAW` | 整理前のCDR3 AA文字列 |
| `SOURCE_ROW` | 元ファイルの行番号またはレコードID |

注釈列は一致判定の最小条件ではありませんが、「どの抗原に対する既知配列か」「一致した配列をどの出典へ戻せるか」を確認するために重要です。

### `Metadata`シートの推奨項目

| 初期項目名案 | 内容 |
|---|---|
| `FORMAT_VERSION` | 例: `QASAS_GENERIC_DB_1.0` |
| `DATABASE_NAME` | 整理後データベース名 |
| `DATABASE_SCOPE` | 対象抗原、疾患、研究目的 |
| `SOURCE_FORMAT` | 元データベース名、ファイル形式、版 |
| `SOURCE_FILE` | 元ファイル名 |
| `SOURCE_SHA256` | 元ファイルの同一性確認用ハッシュ |
| `CONVERTER_VERSION` | 整理アプリの版またはGitコミット |
| `CONVERTED_AT` | 変換日時 |
| `INCLUSION_RULE` | 採用する配列の条件 |
| `EXCLUSION_RULE` | 除外する配列の条件 |
| `NOTES` | 特記事項 |

### `Validation`シートの推奨項目

- 元レコード数
- 出力レコード数
- 除外レコード数と理由別件数
- V／J／CDR3 AAの欠損件数
- 不正なCDR3 AAの件数
- 重複V/J/CDR3キーの件数
- 抗原または出典が不明な行数
- アレル情報が存在する行数と存在しない行数
- 警告と整理時の判断内容

## 6. 重要な意味上の規則

### Vコール・Jコール

- 元データにアレル情報がある場合は保持します。
- 元データにアレル情報がない場合、根拠なく`*01`などを補いません。
- 複数候補がある場合は元文字列を`*_RAW`へ残し、標準列の表現規則を形式仕様に固定します。
- 整理アプリでの表記統一と、旧QASAS／Kobe／CDR3のみ方式の照合規則を混同しません。

### CDR3 AA

- アミノ酸配列と塩基配列を区別します。
- 大文字化、空白除去、端部の扱いなど、実施した機械的処理を記録します。
- C／Wなどの端部を含むかどうかは元データを保持し、根拠なく切り落としません。
- 停止コドン、不明残基、空欄を検出し、採用・除外規則をValidationへ残します。

### 注釈と抗原特異性

- Kobe方式とCDR3のみ方式では、エピトープなどの注釈はV/J/CDR3一致判定そのものには使用しません。
- 旧QASAS方式では、`Binds to`や`Neutralising Vs`に相当する列が存在する場合、候補行の選別に使用します。
- 結合・中和列が存在しない場合、V/J/CDR3が有効な行は候補になり得ます。そのため、整理済みデータベース自体が目的の抗原特異的配列集であることを確認します。
- 異なる抗原の配列を混在させる場合は、`TARGET_ANTIGEN`などで追跡できるようにします。

### COUNT

- 汎用データベースにCOUNT列は必須としません。
- 文献数、患者数、観測回数などが存在する場合は、その意味を列名とMetadataで明示します。
- データベースの件数情報を、検体レパトアのRead数や頻度として扱いません。

## 7. データベース整理アプリの画面・処理案

1. 元データベースファイルを選択する
2. 入力形式を自動判定または一覧から選択する
3. シート、ヘッダー行、V、J、CDR3 AA列をプレビューする
4. 抗体ID、抗原、エピトープ、中和、出典などの注釈列を対応付ける
5. 自動対応付けの結果を利用者が確認・修正する
6. 欠損、不正配列、重複、由来種、抗原範囲を検証する
7. 採用・除外予定件数と理由を表示する
8. 元ファイルとは別の場所へ汎用データベースExcelを保存する
9. 出力Excelを再読込し、形式仕様とValidationの整合性を確認する

入力データベースごとの読込処理はアダプターとして分離し、新しい形式を追加しても既存形式の整理結果が変わらない構造を目標とします。

## 8. QASASのデータベース選択ボタン

QASAS Kobe Ver 2.0の単独検体画面と経時・複数検体画面には、次の選択ボタンを配置します。

- `CoV-AbDab（CSV）`: 現在使用できる既定のデータベース形式
- `汎用データベース（今後対応）`: 将来の汎用データベースExcel入力場所

汎用データベースボタンは、仕様と専用ローダーが完成するまで無効状態にします。現在のCoV-AbDabローダーや照合計算は変更しません。

## 9. 汎用データベースボタンを有効化する完了条件

- `QASAS_GENERIC_DB_1.0`のシート名、列名、許容値が確定している
- V、J、CDR3 AAの検証規則が確定している
- 注釈列と元列の追跡規則が確定している
- 専用の汎用データベースローダーが実装されている
- 未知の形式バージョン、必須列欠損、不正値を安全に拒否できる
- CoV-AbDabの既知行を汎用形式へ整理し、意図した照合キーと結果が一致する
- 元データから汎用Excel、QASAS読込後まで行数と除外理由を追跡できる
- 単独解析と経時解析の両方で試験に合格する
- DB形式と形式バージョンが処理ログ・Excel結果・再現性情報へ記録される
- README、形式仕様、操作手順、テストデータが揃っている

## 10. 実装時の段階案

1. 実際に追加する複数データベース形式のサンプルを収集する
2. V/J/CDR3 AAと注釈列を比較し、最小共通仕様を決める
3. `QASAS_GENERIC_DB_1.0`を確定する
4. 共通検証エンジンと最初のデータベースアダプターを作る
5. プレビュー、列対応付け、Validation出力を作る
6. CoV-AbDabを含む既知データで整理前後を検証する
7. QASAS汎用データベースローダーを実装する
8. `汎用データベース`ボタンを有効化する
9. 単独・経時結果へDB形式、形式バージョン、元ファイル情報を記録する

## 11. 実装開始時に最終決定する事項

- 正式なシート名と列名
- DB IDの必須性と一意性規則
- 複数V/J候補の表現方法
- CDR3 AAの許容文字と端部処理
- 重複V/J/CDR3行を統合するか
- 注釈が異なる同一配列の保持方法
- 抗原不明行を許容するか
- ヒト以外の配列の扱い
- 旧QASAS方式で使用する結合・中和列の標準名
- エラーと警告の境界

これらは実データを確認せずに固定せず、追加するデータベースごとの意味と研究目的を確認して決定します。
